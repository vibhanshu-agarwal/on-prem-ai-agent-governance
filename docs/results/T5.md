## Behaviour, per requirement

1. **PII (Presidio).** Per agent policy each entity is `mask`, `block` or `allow` on input; output is `redact`/`block`/`allow`. Defaults: email, phone, IBAN, IP are masked; credit card and SSN block; `hr-agent` (restricted) blocks IBAN and secrets too. Errors name entity types and counts only, never values, and the audit log carries no prompt text. Verified end to end: the echo provider records what it received, and it received `<EMAIL_ADDRESS>`, never the address.
2. **Deterministic rules.**
   - *Injection*: weighted heuristics (instruction override, prompt-reveal, role hijack, chat-template markers, exfiltration, hidden characters, and more) with NFKC/zero-width normalisation, run on **untrusted content**: `role: tool`, messages flagged `"untrusted": true` (stripped before forwarding), or `<untrusted>...</untrusted>` spans. Actions `block | neutralize | flag | off`; `scan: all` extends to user messages.
   - *Tool authorization*: an agent may only declare, replay or receive tool calls for tools in its allowlist (default: none). Checked on the request (declared tools, forged assistant history) and on the model response (including streamed tool calls).
   - *Output rules*: AWS/GitHub/`sk-`/Slack/Google/JWT/private-key/password-assignment patterns are redacted or blocked.
   - *Consequential actions*: tools carry a class (`external_send`, `payment`, `destructive_write`) and/or an action name (`payment.release`, `git.push`). The response is **withheld** and the caller gets HTTP 428 `approval_required` with `provider_specific_fields.pending[] = {approval_id, tool, action, class, arguments_digest, expires_at}`. A human runs `guardctl approvals approve <id> --by <name>`; the agent retries with `metadata.govguard_approval_id`. An approval is single use (atomic `O_EXCL`), agent-bound, tool-bound, argument-bound (digest) and expires (900 s). Streaming callers get one chunk with `finish_reason: content_filter` and the same JSON.
3. **Config-driven.** `deploy/guardrails/guardrails.yaml` (defaults, teams, agents). The signed bundle (`govpolicy`, T7) is read when `GOVGUARD_POLICY_STORE` + `GOVGUARD_POLICY_TRUST` are set: agent `capabilities` remove tools the agent was never granted (e.g. `git_push` needs `external_send`), and `require_human_approval` names always gate. It can only tighten. Tampered/unsigned/missing bundle => 503 fail closed. Swap point: `engine.type: package.module:factory`; proven by `tests/guardrails/swap_engine.py` (a different detector, same pipeline, nothing else changed).
4. **False positives.** `guardctl override grant --agent A --rule injection|secrets|pii|pii.<ENTITY>|tool.<name> --ttl 15m --reason "..." --by alice`. Reason (>= 10 chars) and approver are mandatory, TTL is capped (24 h), it is scoped to one agent and one rule, revocable, and grant/use/revoke are all audit events (`override.used` names the override id and approver). Approval gates are **not** overridable (rejected at grant). The gateway picks up a grant/revoke within about 1 s.
5. **Fail modes by data classification** (`fail_modes` in the YAML): `restricted` and `confidential` **fail closed** (503 `guardrail_engine_unavailable`, response withheld too), `internal` **degrades** to the builtin regex engine (still masks structured PII; audited `degraded: true`), `public` **fails open** (audited). Proven through the real gateway with a second gateway whose Presidio URL points nowhere (the shared Presidio is never stopped). A circuit breaker plus a background `/health` probe make refusal immediate, and a health check runs before a skipped call is trusted, so a clean prompt cannot slip through an outage. Deterministic rules keep working while the engine is down.
6. **Tests** in `tests/guardrails/` cover every item above (see the file list: rules, pii, injection_and_tools, overrides, engine_and_failmodes, signed_policy, live_gateway, live_failmodes, live_presidio, live_latency).

## Latency

Target: total gateway overhead p95 <= 150 ms, prompts up to 8K tokens (Week 0). Host: Docker Desktop, 12 CPUs, **shared with other agents' concurrent test runs**, so absolute numbers are noisy (identical code measured 45 ms and 140 ms p50 minutes apart in the host-side benchmark).

**Authoritative: paired A/B through two identical isolated gateways** (`bench_gateway.py`, n=80 pairs per row, alternating calls, unique prompts so no cache hits, PII present, provider-free mock model). ON = hook + real Presidio, OFF = hook disabled. "Added" is the per-pair difference.

| Prompt | ON p50 / p95 | OFF p50 / p95 | **Added p50 / p95 (ms)** |
|---|---|---|---|
| ~100 tokens, PII | 106 / 159 | 73 / 124 | **23 / 76** |
| ~2K tokens, PII | 118 / 176 | 86 / 139 | **29 / 78** |
| ~8K tokens, PII | 109 / 164 | 77 / 111 | **28 / 74** |
| ~8K tokens, clean | 95 / 141 | 86 / 119 | **7 / 44** |

Hook-internal timing (its own audit records, same run): 8K tokens with PII p50 29 / p95 50 ms; 8K clean p50 5 / p95 13 ms; response phase 0.2 ms when there is nothing to redact.

Host-side pipeline benchmark against Presidio over the Docker Desktop loopback proxy (`bench.py`, n=60; adds a proxy hop and is the noisiest measurement): cold 8K single message with PII p50 62 / p95 103 ms; agent turn (8K history cached + 300 new tokens) p50 1 / p95 5 ms, with PII in the new part p50 52 / p95 138 ms; tool result 8K scanned for injection p50 13 / p95 19 ms; 500-token response with PII to redact p50 42 / p95 85 ms. The 500 and 2000-token cold rows show p95 of 230 to 250 ms in that run (host contention spikes; the same rows were 84 to 140 ms in other runs), which is why the gateway A/B is the authoritative figure.

How the target was met (what I measured, in order):
- Presidio analysing an 8K-token prompt whole costs **0.5 to 1 s** (spaCy is linear in text length, roughly 0.1 ms per word plus a fixed 30 to 60 ms per call; even a stripped-down NLP pipeline was still ~200 ms). Naive integration would fail the target by 4x to 8x.
- **Candidate windows**: for pattern-based entities a cheap superset regex finds the few places that could hold PII; only +/-160 chars around them go to Presidio, and clean text makes **no call**. Parity with whole-text analysis is tested against the live analyzer (24 random prompts, 30+ entities, identical spans). Policies that ask for NER entities (PERSON, LOCATION) get whole-text analysis (slower).
- **Per-message cache** (agents resend history every turn): an 8K history costs ~1 ms after the first turn. **One analyzer call** for all uncached messages of a request. Long text is chunked and analysed concurrently across 3 analyzer workers.
- Literal-anchor pre-checks made the injection scan 5x faster on prose (25 to 5 ms for 48K chars); the per-character Unicode path runs only for non-ASCII text.
- **Audit I/O must never run on the gateway event loop.** The first A/B run showed 1 to 2.5 s tail spikes on the guarded gateway only. Cause: synchronous appends to the audit file on a Windows bind mount. The sink now queues and a daemon thread writes (and the override directory is snapshotted by a refresher thread). After that, no spikes (max added 155 ms over 320 pairs). Note the bind-mounted file can still lag by seconds; tests poll.

## False-positive and false-negative notes (measured, not guessed)

- Default Presidio registry labelled `123-45-6789` as `UK_NHS` and missed it as SSN. Country recognizers (NHS, ES/IT/PL ids) fire on ordinary digit strings, so the pinned registry (`presidio-recognizers.yaml`) keeps only structured US/global recognizers. Presidio's SSN recognizer also rejects sample-looking numbers (invalid area/group), which is correct behaviour but surprises test authors.
- **Phone**: an unlabelled phone scores 0.4 (0.75 next to a word like "phone"). It also scores 0.4 for a 10-digit invoice number (`amount 1234567890`). Threshold 0.5 skips both: **misses unlabelled real phones** but keeps invoice numbers intact. `hr-agent` uses `entity_thresholds: {PHONE_NUMBER: 0.4}` (recall over precision for restricted data). Tune per agent.
- **IP_ADDRESS** matches version strings (`1.2.3.4` scores 0.6). Coding agents will see version numbers masked; raise the threshold or override per agent if that hurts.
- **NER entities (PERSON, LOCATION)** are off in the pilot policy: names and place words in ordinary business text give many false positives (Presidio labelled "Angela Merkel" and "Paris" correctly, but also common nouns in noisy text). Available by listing them in `pii.entities`; they force whole-text analysis (~0.5 to 1 s for 8K tokens).
- **Credit cards** are Luhn-validated: a 16-digit order number that fails Luhn is not flagged (`4111 1111 1111 1112`). No false positive, but a mistyped real card is also not flagged.
- **Injection heuristics** are a screen, not a defence. Known false positive: an ordinary document that quotes "ignore the previous instructions in the appendix" trips it (asserted in a test; this is what overrides are for). Deliberately weak patterns stay below the threshold on their own ("send the invoice to accounts@vendor" scores 2 of 3). Known false negatives: paraphrase, other languages, instructions split across messages, text inside images. Scanning targets untrusted channels only, so an injection typed into the **user** channel is not screened (`scan: all` opts in).
- **Secrets**: the `password_assignment` pattern matches prose like `token: abcdefgh1`. Placeholders are written as `<REDACTED:kind>` because an earlier form (`<SECRET:...>`) re-matched the password pattern on the output pass (found by an end-to-end test).
- Windowed analysis assumes every requested entity is pattern-based with a digit/`@`/dotted-quad signature; it falls back to whole-text otherwise. Crypto addresses and MAC addresses are not in the signature set (not configured).

## Simplifications and gaps (honest list)

- **Only chat completions are guarded** (`completion`/`acompletion`). `/v1/responses`, legacy `text_completion`, embeddings and the Anthropic-format route bypass the hook. Closing that is T9 (either guard them or disable those routes on the agent-facing gateway).
- **The approval gate is enforced at the gateway on the model's request.** An agent that calls a tool without asking the model bypasses it, so real enforcement also needs the tool executor (T4 tool broker / MCP gateway) to demand the approval id. Approval is a CLI + files here; no ticketing, no approver-independence check, no notification.
- **Streaming is buffered** for guarded agents (bounded by `max_tokens`, adds time-to-first-token equal to full generation). `streaming: passthrough` per agent skips output guardrails (audited). Blocks on streams are 200 responses with `finish_reason: content_filter` (headers were already sent), not HTTP errors.
- **Policy source is split**: guardrail-specific settings (`tools.allow`, PII actions, fail modes) live in the YAML because the T7 agent schema rejects unknown fields. The signed-bundle overlay is unit-tested with real signed bundles but is **not mounted in the running compose stack** (opt-in via env + mounts). Moving guardrail settings into the signed policy is the natural follow-up.
- **Audit** is an append-only JSONL file (`.local/guardrails/audit.jsonl`) behind an `AuditSink` Protocol, not hash-chained and not T3's Postgres audit table. Rotation is not implemented; `record_clean: true` logs every request (useful evidence, wasteful in production).
- English only; the analyzer runs 3 gunicorn workers (about 1 GB of RAM each because of the spaCy large model).
- LiteLLM runs one worker here; the pipeline's caches and breaker are per process, the file stores are shared, so multi-worker would work but was not tested.
- `mock-echo` is a test-fixture model in the production `config.yaml`; harmless without the overlay, but T9 may prefer generating it for tests only.
- `tests/foundation` on the shared stack: 3 failures remain that are **not** from this task (default `max_tokens` is now 96 via the T2 token policy, key metadata now carries `token_policy`/`attribution`, agent containers now sit on the agents network). One failure was mine (the echo provider joining the providers network) and is fixed by removing it after the tests.

## How to run

```
.venv/Scripts/python -m pip install -r tests/guardrails/requirements.txt
.venv/Scripts/python -m pytest tests/guardrails                     # everything (about 5 min)
.venv/Scripts/python -m pytest tests/guardrails -k "not live"       # unit tests only (seconds, no stack)
PYTHONPATH=services/guardrails python -m govguard override grant --agent coding-agent --rule injection --ttl 15m --reason "runbook quotes the phrase" --by alice
PYTHONPATH=services/guardrails python -m govguard approvals list --state pending    # then: approvals approve <id> --by bob
.venv/Scripts/python services/guardrails/bench.py                   # host-side pipeline latency
```
The stack needs `scripts/bootstrap.sh` (Presidio now starts with it). State (audit, overrides, approvals) is in `.local/guardrails/` (gitignored, bind-mounted into the gateway). The live tests publish Presidio on `127.0.0.1:5301/5302` through `tests/guardrails/stack/compose.echo.yml`; production keeps it internal.
