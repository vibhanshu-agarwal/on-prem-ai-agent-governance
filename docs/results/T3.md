## Feature notes

**1. Identity register.** One record per agent (`POST /v1/agents`): owner, team, budget, model allowlist, gateway keys (hash + where the raw key lives in the SecretStore), workload selector (container labels, default `govpilot.agent_id=<id>`), OIDC subjects, other credentials (values go to the SecretStore, never the register), sandbox tier, capabilities, parent/root/depth for delegates. Keys are either provisioned (own LiteLLM virtual key with metadata `agent_id`, `root_agent_id`, `team`) or linked by alias; the three T1 agents are seeded from config and linked to the keys `scripts/bootstrap.sh` made. A minimal admission rule rejects `executes_code` below the `microvm` tier (T7 owns the full gate).

**2. Stop sequence** (`POST /v1/agents/{id}/stop`). Desired state is persisted first (so the reconciler backs the stop up even if the request dies), then, each phase in parallel across agents and delegates:
1. gateway: `/key/block` every registered key, then every other key whose metadata names the agent;
2. network: a short-lived helper container joins the agent's network namespace and installs iptables `REJECT --reject-with tcp-reset` for TCP (and DROP for the rest); the next segment from the gateway/auth proxy is answered with RST, so the chokepoint side of every live stream dies. The adapter then waits (up to 3 s) until the chokepoints (`gov-gateway`, `gov-authproxy`) hold no established connection from the agent's IPs, and disconnects the container from the governed networks;
3. desired state: restart policy set to `no`, then stop (SIGTERM, SIGKILL after 2 s);
4. credentials: tool/DB creds revoked in the SecretStore; OIDC subjects disabled at the IdP (no new tokens);
5. verify: keys blocked **and** a real request with the raw key refused, workloads not running, restart policy `no`, detached, creds revoked, subject disabled, and after 1.5 s nothing came back.
Every phase is timed and audited; the report is stored (`GET /v1/stops/{id}`).

| 2 | 0.075 s | 26 ms | 1.71 s | 2.06 s | 3.82 s | 5.35 s |
| 3 | 0.072 s | 29 ms | 1.67 s | 2.05 s | 3.77 s | 5.31 s |

"First refused request" is measured by a background client hammering the gateway with the agent's key every 50 ms: 0 successful requests after the first refusal in every run. In every run the stream in flight was cut: `connections_before=1`, `connections_after=0` at the chokepoints, and no token reached the agent after the network phase ended (the agent log shows the stream never completed). The desired-state phase is ~2 s because the rogue agent is PID 1 and ignores SIGTERM, so it waits for the grace period.

Restart and persistence: after a stop, `docker start` on the container was reverted by the reconciler in 2.1 to 2.9 s; a compose-managed agent with `restart: always` re-created by `docker compose up -d` was stopped again in 2.6 to 3.6 s and stayed down. Resume (`POST /v1/agents/{id}/resume`) reverses a stop (unblock keys, reattach networks with their aliases, restore restart policy, start); revoked credentials stay revoked.

**3. Bulk quarantine** (`POST /v1/quarantine/preview` -> `POST /v1/quarantine/actions` -> approvals). Selectors: `team`, `image`, `labels`, `host`, `agent_ids`, `all`. The preview returns the blast radius (agents, keys, workloads running, credentials, subjects, delegates, and unregistered workloads matching image/labels) and whether it is fleet-wide (>= 4 agents, >= 2 teams, or `all`; config). Firing requires the `operator` role and a human (`kind=user`) principal. Fleet-wide actions need two approvals from two distinct humans other than the requester. At fire time the selector is re-resolved; if it now matches agents that were not in the preview, the action is refused as stale. An executed action leaves an active rule the reconciler enforces (a new container with that team label was stopped on sight); `lift` reverses it. Measured: 3 streaming agents by team, 6.6 s total, all verified.

**4. Emergency stop.** `gov-estop` (HTTP, bearer token checked against `ESTOP_TOKEN_SHA256`, `X-Estop-Operator` required) and `python -m govcp.estop.cli` (host, needs only the gateway admin key and Docker). It finds handles without the register: gateway keys by alias / `metadata.agent_id` / `root_agent_id` (catches delegates), containers by label; team stop uses the team's keys and `govpilot.team` label. Test: `gov-control-plane` and `gov-cp-postgres` stopped, control-plane API unreachable, estop stopped a streaming agent in 2.4 to 2.6 s (verified), the CLI stopped a second one, a bad token was refused and journaled. The estop journal is its own hash chain (JSONL); when the control plane is back it ingests new entries into the main audit log and marks the agents stopped.

**5. Audit log.** Table `audit_log` in the control plane's own Postgres. Each row stores `prev_hash` and `hash = sha256(prev_hash || canonical_json(seq, ts, actor, action, target, severity, details))`; appends are serialised with an advisory lock. The app role `cp_app` has only SELECT and INSERT on it (checked in `information_schema`); UPDATE/DELETE/TRUNCATE fail with insufficient privilege, and a trigger rejects them even for the owner. `GET /v1/audit/verify` recomputes the chain; editing one record or dropping one is detected at the exact sequence number. Every register/stop/quarantine/approval/discovery/delegation/estop/reconciler action is recorded; `GET /v1/alerts` lists `severity=alert`.

**6. Discovery queue.** `POST /v1/discovery/proposals` (role `feed`; the feed name is the authenticated client id). Proposals land `pending`, `budget_usd=0`, **no gateway key** (none exists at the gateway). Auto feeds must include evidence; duplicates by fingerprint are folded; a per-feed daily cap is enforced with an atomic counter (feed-test: 3/day -> 4th gets 429 and an audit record). Only a human owner of the target team can approve (owner of another team, and the feed itself, get 403); approval creates the agent and its key with the approved budget. An unregistered SSO identity hitting the auth proxy gets 403 and is proposed via the `idp-first-use` feed.

**7. Identity stand-in and auth layer.** `gov-idp` issues RS256 JWTs (client_credentials for agents/feeds/services, password grant for the five demo humans with roles admin/operator/approver/owner/viewer), JWKS and a discovery document. `gov-authproxy` validates the JWT (issuer, audience `govpilot-gateway`, expiry, signature), resolves the subject to the agent's **own** LiteLLM key through the control plane (key minted at first use if missing), and forwards/streams to the gateway with that key; it fails closed if the control plane is unreachable. Measured SSO stop: the next request with the same JWT was refused **0.12 s** after the stop decision while the token still had **894 s** to live; the IdP also refused new tokens for that client; the SSO agent's in-flight stream through the proxy was cut. Forged tokens and tokens for the wrong audience get 401.

**8. Delegation attenuation.** Each agent gets a root capability token at registration (macaroon-style: HMAC chain over caveats `agent =`, `budget_usd <=`, `models in`, `max_depth <=`, `expires <`). `POST /v1/delegations` with the parent's token mints a sub-agent: registered child identity (`<parent>.<name>`, depth+1), its own gateway key with the narrower budget and models, and the parent's token with caveats appended. Denied and alerted (`delegation.broadening_denied`): budget above the parent's remaining delegable budget, models outside the parent's set, depth beyond the cap (2), lifetime beyond the parent's. Edited tokens fail the signature (`delegation.invalid_token`); appending a broader caveat offline cannot widen scope (intersection semantics); appending `agent = hr-agent` fails the lineage check against the register (`delegation.chain_rejected`). Out-of-scope use through the auth proxy (`Authorization: Macaroon ...` with a model outside the subset) is refused and alerted (`delegation.scope_violation`), and the gateway independently refuses the child key for that model. Stopping a parent stops its delegates and kills the lineage for further minting.

## Review fixes (2026-09-29)

- **Verify checks live state, not the stop's snapshot.** `StopService.verify` re-lists workloads by each agent's selector and re-scans gateway keys by metadata; a container re-created or a key minted between the block phase and verification now fails the stop (`workload.appeared_during_stop`, `gateway.key_blocked` for metadata-found keys) instead of passing unseen.
- **Stop-in-progress window closed.** `desired_state` flips at phase 0 but `status` only at the end (~5 s). Delegation minting/use (`verify_holder`) and first-use key mapping (`AccessService._key_for`) now also require `desired_state == running`, so a stop in progress cannot mint a fresh unblocked key or child.
- **Dual control:** an action whose preview expired before the last approval is refused as stale (approvals can arrive long after the humans looked), and a grown *unmanaged* blast radius (new unregistered workloads matching image/labels) is stale too, not just new registered agents.
- **JWT `kind` defaults to machine.** A token without a `kind` claim is a `client`, so human-only actions (bulk quarantine, approvals) fail closed against an IdP that lacks the claim.
- **Read endpoints need a role.** `GET /v1/agents|stops|quarantine/*|discovery/proposals|audit|alerts` require viewer/operator/approver/owner; any machine client could previously request a control-plane-audience token from the IdP and read the whole register and audit log.
- Auth proxy strips `api-key`, `x-api-key`, `x-litellm-api-key`, `x-govpilot-agent` from callers (only the proxy's own credential reaches the gateway); estop-journal ingestion runs on a tick counter instead of a wall-clock modulo that could skip.

## Findings and deviations

1. **No `ss -K` on this kernel.** Docker Desktop's WSL2 kernel (6.18) does not support SOCK_DESTROY, so `ss -K` kills nothing (tested). The Docker adapter instead injects RSTs with iptables inside the agent's netns and then confirms at the chokepoints that no connection remains. Consequence: the gateway/auth-proxy side is torn down (so the upstream stream and its spend stop), but the agent's own socket is not notified; it simply receives nothing more until the process is stopped, which the full sequence does next. An idle keep-alive connection is only reset when the chokepoint next writes; the network disconnect then severs it.
2. **`/team/block` not relied on.** In a probe, a key of a just-blocked team still got 200 on `/v1/models`. The stop and bulk paths block every key individually (including keys found only by metadata), which was effective on the next request every time.
3. **SSO agents are on their own network** (`govpilot_agents_sso`) rather than the T1 `agents` network, so T1's "only the gateway on the agents network" invariant holds and SSO agents cannot bypass the auth layer.
4. **Port 4100 is taken by T2's stack**, so the auth proxy publishes on 127.0.0.1:4180.
5. **Docker socket** is mounted into `gov-control-plane` and `gov-estop` (root-equivalent on the host), and the quarantine helper runs with `NET_ADMIN` in the target's netns. The control plane and estop also hold the LiteLLM master key. A real deployment uses a namespaced Kubernetes service account and a scoped gateway admin key.
6. The rogue sample agent runs as PID 1 and ignores SIGTERM, so each stop waits the 2 s grace period; that is realistic, and the grace period is config.

## Simplifications vs an enterprise deployment

| Here | Enterprise | Swap |
|---|---|---|
| Stand-in IdP with demo users/passwords from `.local/control-plane.env` | Corporate OIDC (Keycloak/Entra/Okta), MFA, groups -> roles | IdentityProvider adapter: verify is generic OIDC already; subject disable via SCIM/Graph |
| Docker labels + restart policy + reconciler as the "controller" | Deployment/Job desired state owned by Kubernetes | Orchestrator adapter (scale to 0 / suspend) |
| iptables RST in the agent netns + network disconnect | NetworkPolicy/Cilium deny + conntrack flush (tested per CNI) | NetworkQuarantine adapter |
| Secrets in a 0600 JSON file on a volume; tool/DB creds simulated | Vault/KMS; real revocation per system | SecretStore + CredentialRevoker adapters |
| Audit in local Postgres with hash chain | Also streamed off-host to a SIEM/WORM store, chain head anchored externally | AuditSink adapter (fan-out) |
| Estop auth = one static bearer token, journaled | Break-glass with hardware token / two-person rule, own host | estop config |
| Single control-plane instance, reconciler in-process | HA pair with leader election | deployment |
| Simple tier/capability admission rule | Signed policy-as-code gate at admission (T7) | T7 |
