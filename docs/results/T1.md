## What was built

- `services/mock-provider/`: OpenAI-compatible `/v1/chat/completions` (stream + non-stream), `/v1/models`, `/health`. Deterministic: prompt tokens = words + 3 per message; completion tokens = `max_tokens` (or 32 default, capped at 4096); content is `tok0 tok1 ...`. `usage` block in non-stream responses and in the final stream chunk (an empty-choices chunk before `[DONE]`). Env config: `PROVIDER_NAME`, `FIRST_TOKEN_LATENCY_MS`, `PER_TOKEN_LATENCY_MS`, `SLOW_MODE`/`SLOW_FACTOR`, `MODELS`, `API_KEY_SHA256`. Any model id ending `-slow` (`mock-local-slow`, `mock-remote-slow`) streams at `PER_TOKEN_LATENCY_MS * SLOW_FACTOR` (500 ms / 1 s per token) for later in-flight teardown tests.
- `deploy/docker-compose.yml` (project `govpilot`, containers `gov-*`): postgres, redis, mock-local, mock-remote, gateway. All have healthchecks and `--wait` brings them up healthy.
- Networks: `govpilot_agents` (internal; only `gov-gateway`), `govpilot_providers` (internal; gateway + both mocks), `govpilot_backend` (internal; gateway, postgres, redis), `govpilot_edge` (normal bridge; gateway only, solely so Docker can publish `127.0.0.1:4000`).
- `deploy/litellm/config.yaml`: four models (`mock-local`, `mock-local-slow`, `mock-remote`, `mock-remote-slow`) with per-token pricing (local $1/$2 per M in/out tokens; remote $5/$15), `model_info.max_output_tokens: 1024` (the ceiling native budget reservation uses), DB-backed virtual keys, `fail_closed_budget_enforcement: true`, shared `coordination_redis`, `DISABLE_ADMIN_UI`, `LITELLM_MODE=PRODUCTION`.
- `scripts/`: `gen-env.sh` (random secrets into gitignored `deploy/.env`; `deploy/.env.example` committed), `bootstrap.sh` (+ `provision.py`, stdlib only), `teardown.sh` (`--volumes`, `--purge`). Provisioning creates teams `hr` ($5), `finance` ($10), `engineering` ($20) and keys `hr-agent` ($1, `mock-local`), `finance-recon-agent` ($2, local+remote), `coding-agent` ($5, all four models), each with `max_budget`, `budget_duration: 30d`, metadata `{agent_id, team}`, model allowlist. Keys land in `.local/agent-keys.json` (gitignored). Re-running is idempotent.
- `tests/foundation/`: 31 tests (run: `.venv/Scripts/python -m pytest tests/foundation`, after `uv venv .venv && uv pip install -r tests/foundation/requirements.txt`).

## Deviations from the plan, and why

1. **Not the `-stable` image, and not 1.83.x.** The newest `-stable` tag is `v1.83.14-stable` (exists, >= 1.83.7), but I inspected it: it has **no budget reservation and no `fail_closed_budget_enforcement`** (source grep on the image: absent). Reservation first appears in 1.84.x; `fail_closed_budget_enforcement` in ~1.90 (present in 1.90.7, absent in 1.88.6). LiteLLM stopped publishing `-stable` tags after 1.83.x; later releases use plain `vX.Y.Z` tags. The plan says native reservation first with fail-closed, so I pinned `v1.100.3` (latest patch of a minor line that is several days old; 1.103.0 is one day old). Both features verified in that release's source. Consequence: the pin is not a "stable"-labelled image; the reviewer/owner may prefer another >= 1.90 release.
2. **Gateway also joins a non-internal `edge` network.** Docker cannot publish host ports for containers that are only on `internal: true` networks. Agents never join `edge`, so the isolation requirement is unaffected. Consequence: the gateway has outbound internet routing (needed anyway for future approved remote providers); tighten in T9 if desired.
3. **Mocks verify a hashed key.** To satisfy "dummy api_key held only in the gateway env" while still letting the mock reject unauthenticated direct calls, the mock env carries only `API_KEY_SHA256`.
4. **Extra models** `mock-local-slow` / `mock-remote-slow` beyond the two required, for the slow-stream requirement (per-model rather than only per-instance, because the gateway cannot forward per-request headers from clients easily). `SLOW_MODE=1` also works per instance.
5. Redis needed `general_settings.coordination_redis`. `router_settings.redis_*` alone left Redis unused (no counters written); found and fixed by inspecting keys. Both are set.

## Findings and open issues (handed to T2 and later)

- **No native per-key `max_tokens` ceiling.** The default ceiling is per model (`litellm_params.max_tokens`) and only applies when the client omits `max_tokens`. A client sending `max_tokens: 100000` is forwarded as-is (mock capped it at 4096). Native reservation clamps its *reservation estimate* to `model_info.max_output_tokens` (1024), but the request is not clamped, so a large request can spend more than it reserved. T2 must test this; likely gap-fill is a gateway pre-call hook that clamps or rejects `max_tokens` above the agent ceiling (T4 callbacks dir / T5).
- Redis was not fault-tested here (fail-closed with Redis or Postgres down is T2 scope).
- Gateway runs as root inside its container and the config volume is read-only; read-only rootfs and non-root are T9.
- LiteLLM logs harmless warnings about cache-cost fields for custom-priced mock models.
- `HANDOFF.md` and `docs/PILOT-PLAN.md` showed uncommitted modifications from someone else during this task; I did not touch or commit them.
- Windows note: run scripts with Git Bash; `docker run` probes in tests use `govpilot/mock-provider:1` as the stand-in agent container.
