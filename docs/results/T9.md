# T9 results: hardening + release

Date: 2026-09-29. Result: gateway hardened and fronted by an allowlisting proxy, review leftovers fixed, hardening
checks scripted (`tests/hardening`, 27 tests), SBOMs and digest pins committed, third-party notices and operator
runbook written. Suites on the final stack, all passing: hardening 27, foundation 32, control 109, guardrails 125,
agents 120, discovery 44, and the 28 acceptance tests (details in section 7).

## 1. Gateway hardening (`deploy/hardening/`)

| Piece | Where | What it does |
|---|---|---|
| Overlay | `deploy/hardening/compose.hardening.yml` | Applied on top of `deploy/docker-compose.yml` by `scripts/bootstrap.sh`, `scripts/up.sh`, `scripts/acceptance.sh`, `scripts/teardown.sh` and the guardrail test stacks. The base file alone still works (unhardened variant, used to bisect problems). |
| Allowlist proxy | `gateway-edge` (`nginxinc/nginx-unprivileged:1.27-alpine`, pinned) + `deploy/hardening/nginx.conf` | Takes the alias `gateway` on the agents network. Exact-match locations for `POST /v1/chat/completions`, `/v1/completions`, `/v1/embeddings` (and the same without `/v1`), `GET /v1/models`, `/models`, `/health/liveliness`, `/health/liveness`; everything else is `403 forbidden_route` from nginx. Matching is on the decoded, slash-merged path and the upstream receives that normalised path, so `..`, `%2e%2e`, `//`, `;`, case and trailing-slash tricks do not smuggle a route (51 probes in the tests). Streaming passes through unbuffered; a client disconnect closes the upstream so a cut stream stops generating. Body limit 8 MB, header/body timeouts, `server_tokens off`, Docker DNS re-resolved every 5 s so a recreated gateway is found. |

It keeps the alias `gateway` on `backend`, where the control plane, estop and auth proxy call its admin API: the separate admin path. The proxy reaches it as `gateway-core` on `gwfront`. Operators still have `127.0.0.1:4000` (admin + inference) on the host. |
| Auth proxy | `services/control-plane/govcp/authproxy/app.py` | Same inference-only allowlist (`ALLOWED_ROUTES`), checked before authentication: an SSO agent's resolved key cannot reach `/v1/key/*`, `/v1/team/*`, `/v1/mcp-rest/*` either. |

| Other services | overlay + `compose.control-plane.yml`, `compose.observability.yml`, `compose.discovery.yml` | Postgres x2, Redis, mock providers, control plane, IdP, auth proxy, estop, migrate, discovery: `cap_drop ALL` (Postgres/ClickHouse keep only the caps their entrypoints need to chown and drop privileges, listed in the test), `no-new-privileges`, read-only root fs with tmpfs where the image tolerates it, pid/memory limits. Agents, broker and status page already were read-only, non-root-capable, cap-dropped (T4/T10). |

**Not done, with reasons**

* *Guardrail audit through the control-plane `AuditSink` port.* Not small: the hook runs inside the gateway, which has
  no identity toward the control plane, so it needs an authenticated ingest endpoint, a non-blocking batching client
  inside the callback (the hook writes from a background thread on purpose because the bind-mounted file lags), a
  retry/spool story for control-plane outages and a schema for the guardrail events. Design for a follow-up: the
  gateway keeps writing `audit.jsonl` (it must keep working when the control plane is down); a small forwarder
  container tails it and `POST`s batches to a new `/v1/internal/audit-ingest` (client-credentials token, like the
  auth proxy), which appends through `AuditSink`. The estop-journal ingest (`/v1/admin/estop-ingest`) is the pattern.
* Other T3/T8 leftovers not assigned to T9 and untouched: `/v1/delegations` rate limit, auth proxy hard-codes the OIDC
  adapter, `reconcile.py` post-check revert, stream kill only checked on chunk arrival (stalled provider), stream cut
  counts chunks not tokens, hard-killed gateway leaves reservations (safe side).

## 3. Hardening checks (`tests/hardening/`, 27 tests, about 50 s)

1. **Agents cannot reach admin routes**: 51 admin/management/test/smuggling probes from a throwaway container on
   `govpilot_agents`, anonymous and with a real agent key, each must be answered by the proxy (403 `forbidden_route`);
   inference routes still work; `gateway-core` does not resolve from agents and the gateway's backend IP is unreachable;
   the SSO route refuses admin paths before authenticating; the admin path still works for the control plane and the
   operator port (the other half of the split); the nginx config contains exactly the allowed exact locations and a
   denying catch-all.
2. **Gateway filesystem read-only, non-root, no capabilities**: `ReadonlyRootfs`, writes to `/app`, `/etc`, `/usr`
   fail, tmpfs and the guardrail state dir work, uid != 0, `CapEff/CapPrm/CapBnd == 0`, no-new-privileges, limits;
   same for the proxy.
3. **Whole platform**: every `gov-*` container drops ALL caps with only the documented additions, blocks privilege
   escalation, is read-only unless listed; only documented containers are privileged or mount the Docker socket.
4. **No provider credentials outside the gateway**: provider keys and the salt appear in no other container's
   environment; the master key only in gateway, control plane, estop; no credential-like env in agents, the broker,
   the proxy or the status page; agents are not on provider/backend/edge/gwfront networks.
5. **Pinned digests**: every third-party `image:` in `deploy/`, `deploy/hardening/` and the test stacks and every
   Dockerfile base image carries `@sha256:`; the pins equal `release/images.lock`; every running third-party container
   was started from a locked digest.
6. Hygiene: no leaked helper containers; status page isolation.

## 5. Runbook (`docs/runbook/README.md`)

Bring-up and verification, stop an agent (status page, API, estop), bulk quarantine, emergency stop with the control
plane down (four levels down to `docker stop gov-gateway-edge`), break-glass (guardrail engine only, 1 h cap),
backup/restore including the in-place recovery sequence, rollback (per component; LiteLLM migrations are forward-only),
incident response for a suspected gateway compromise (contain, evidence bundle, scope, rebuild from the locked digest,
rotation order, return to service), and the patch SLA for gateway advisories (4 h triage and 72 h patch for actively
exploited; revalidate on every upgrade).

## 6. Deviations and limits (read before relying on this)

* **The operator port is unauthenticated network-wise**: `127.0.0.1:4000` exposes admin routes to anything on the host
  (master key still required). Production should bind the gateway's admin listener to a management network only.
* **Two allowlists** (nginx and the auth proxy) must be kept in step; `tests/hardening` covers both paths, but it is a
  manual coupling. A shared source (generated nginx config) is a follow-up.
* **Provider credentials remain environment variables of the gateway process.** The report recommends an external
  secrets manager; `SecretStore` is a control-plane port only. Not done.
* The proxy adds one local hop. A/B of 80 sequential calls each, through `gateway:4000` (proxy) vs straight to the
  gateway on `gwfront`, repeated twice: p50 62 / 83 ms vs 65 / 61 ms, p95 81 / 117 ms vs 123 / 78 ms. Run-to-run noise on
  this VM is larger than the difference, so the hop's cost is not measurable here (well under the noise; M-08's
  provider-free overhead, 65 ms p95, is measured from the providers network and does not include it).
* Linux hosts need the gateway's bind-mounted state writable by uid 65532 (`state-init` handles named volumes and the
  repo's `.local/guardrails`).
* The proxy authenticates nothing itself; it is an allowlist, the keys are still checked by LiteLLM.
* Docker Desktop stand-ins remain simplifications (no seccomp/AppArmor profile of our own beyond Docker's default).

## 7. Verification on the final stack

* `scripts/up.sh --recreate` from the running state: exit 0, every `gov-*` container healthy, agents running.
* Suites (each its own pytest process, as `scripts/acceptance.sh` does): `tests/hardening` 27, `tests/foundation` 32,
  `tests/control` 109 (incl. the 5 new domain tests), `tests/guardrails` 125 (the live tests recreate the gateway with the test config and restore the
  production one), `tests/agents` 120, `tests/discovery` 44, `tests/acceptance` 28 tests: **all pass**.
* Caveat on the acceptance run: it was executed in pieces while the discovery and backup regressions above were being
  fixed, not in one uninterrupted pass. Run A (`-x`) passed 9 tests (M-01, M-02, M-03, M-02b and M-04a-d) and stopped at
  M-04e; run B re-ran everything after them (22 passed, 2 failed: M-09 and S8-05); after the fixes the failing tests,
  the discovery suite and the hardening suite were re-run green. The full unattended `scripts/acceptance.sh` (about
  80 min) was **not** re-run after the last edits (proxy log format, discovery feed, `backup.sh`); do that before a
  release tag.
* Environmental note found on the way: the control plane caps each discovery feed at 50 new proposals per UTC day
  (`feedcount:<feed>:<day>` in its KV table). Repeated full acceptance runs exhaust the `gateway-logs` budget and then
  S8-05 and the live discovery tests fail with "never reached the pending queue" until 00:00 UTC. It was exhausted
  (50) before T9 started; for these re-runs the counter row was reset to 0 in the local pilot database and the
  discovery state file cleared. Not a hardening regression, but a trap for anyone re-running the suites twice in a day.

## 8. Follow-up after the T9 review (T10 session)

* **Client `api_key` passthrough (review open item): confirmed on the live gateway and closed.** LiteLLM v1.100.3
  refuses `api_base` / `base_url` natively, but an agent's own `api_key`, `extra_headers` or `headers` replaced the
  gateway's provider credential on the provider call (the mock provider answered 401 "invalid provider api key" to the
  agent's key). A wrong key also put the shared deployment into router cooldown, so every other agent got 429 "No
  deployments available" for the cooldown (seen while probing). `x-litellm-disable-callbacks` does not disable the budget
  guard; `extra_body.api_key` is inert (sent to the provider in the JSON body, not as auth). Fix:
  `deploy/litellm/callbacks/client_credentials_guard.py`, first in the callback list (400
  `client_credentials_not_allowed` before any provider is called; field names audited, never values). Tests:
  `tests/hardening/test_client_credentials_unit.py` (28, offline) and `test_client_credentials_live.py` (11, against the
  gateway; the first one failed on the unpatched gateway). Details and limits: `docs/results/ACCEPTANCE.md`, row 15.
* **M-01 orphan parent runs:** fixed by accounting for them from the agents' durable run journal instead of a tolerance
  (`docs/results/ACCEPTANCE.md`, row 14).
* Still open from the review: discovery ignores self-chosen `gov-*` names and labels.
